# 变更记录

## 未发布（改名 + 换线到 DSH 0.2.1）

本插件**还没有发布过**，因此没有版本号可写——这一节只记录已经落在源码里的变更。

- 兼容线由 DSH `>=0.2.0-rc.2 <0.2.1` **整体换到** `>=0.2.1-alpha.2 <0.2.2`（逐版本验证 `0.2.1-alpha.2`）。上一线的用户留在上一线的插件版本，不维护分叉实现。
- **业务代码一字未改**：0.2.1 的契约面（动态挂载与卸载、volatile 对账、凭据解析与写入、设置写入、只读投影、导航图标补丁）逐项复核后全部成立。隔离宿主上 104 项单测、52 条 GUI 验收（连跑两轮）、12 项鉴权/CSRF、对账幂等与凭据链闭环、导航图标六项几何全过。
- 换线时值得记下的一条：`@deepseek-ai/dsh-mcp-client` 的**代码**与上一线逐字相同（`lib/index.js` 同 sha256），但它运行时依赖的 `@modelcontextprotocol/client` 由 `2.0.0` 升到 `2.2.0`——所以「逐字相同」只对代码成立，行为要实测。本插件在新 SDK 上实测行为不变（连接、工具发现、dispose 与对账全通）。

### 改名 + 换线到 DSH 0.2.0（同一未发布周期内）

- **改名**：包名从 `dsh-mcp-manager` 换成 `dsh-mcp-console`（旧名在 npm 上被第三方占用、发不了版；新名 2026-10-08 实测未被占用）。跟着一起改的还有：profile 条目 id 与模块名（`cordis.patch.yml`）、浏览器 bundle 注册名（`client.js`）、宿主与客户端的 `PLUGIN_NAME` / `SETTINGS_ENTRY` / `SECTION_ID`、两条 HTTP 路由与两个固定请求头名，以及内部短前缀（CSS 类名与导航补丁标记 `dmm` → `dmc`）。**功能一行未改**。

- 兼容线曾由 DSH `>=0.1.7-alpha.1 <0.1.8` **整体换到** `>=0.2.0-rc.2 <0.2.1`（逐版本验证 `0.2.0-rc.2`）。
- 版本门改为从 `DSH_RELEASE_LINE` + `DSH_RELEASE_FLOOR` 常量派生：同线内更低的 channel（alpha/beta）与更小的序列号一律挡在门外（旧的「只挡 alpha 低序号」写法会把 `0.2.0-alpha.9` 误判成兼容）；`install.sh` 有一份等价的 shell 版。
- 新增 `test/manifest.test.js`：守卫「发布线 / 下界 / 验证清单」四处同源，以及**改名落点**（`package.json#name`、`cordis.patch.yml` 的 id/name、客户端 bundle 的 module id、`lib/store.js` 的 `PLUGIN_NAME` 与 `SETTINGS_ENTRY`）必须一致。

## 0.1.0

首个版本。

- 设置页新增「MCP 服务器」分区：列出托管服务器、逐条启停、总开关、新增/编辑/删除（删除需确认）。
- 新增与编辑都走表单弹窗，并且**先验证、后保存**：验证由宿主临时挂载一次真实连接完成（拿得回工具清单），没通过验证就保存不了；保存后等宿主完成对账再显示结果。
- 服务器清单就是本插件在 profile 里的**条目配置**，写入后宿主立即对账：新增/改动挂载、停用/删除卸载，**不需要重启**。
- `stdio` 与 `streamable-http` 两种传输都支持；工具名与手写组合行一致（`mcp__<服务器名>__<工具名>`）。
- 凭据走占位符 `credential:KEY`：settings 里只有键名，值经 DSH credentials 存储读写，界面只显示「是否已配置」，不回显值。
- 修复凭据「保存」点了没反应：客户端补上 `remote.credentials` 注入声明，并在拿不到凭据服务时把原因写在界面上（不再静默失效）。
- 请求头/环境变量的一行是**多行卡片**（名字 + 「凭据」在上，`前缀` / `凭据键名` 各占一行，长键名看得全）；**前缀是档位下拉**（不加前缀 / Bearer / Basic / 其它…，选「其它」可自由输入），下拉箭头自绘（与输入框同高、居中）；键名候选从原生 `datalist` 改成「用过的键」可点小芯片；凭据区的「未配置/已配置」是状态标签，凭据行与「+ 添加请求头」都用 28px 小按钮（与 `dsh-extra-context` 的「+ 添加规则」同尺寸）；导入成功不再弹一句"已转入凭据库"的提示（与字段旁的说明重复）。
- 环境变量与请求头是**结构化行**（名字 / 值 / 「凭据」开关 / 删除）：点「凭据」就能自己取一个键名、也可以从前后的条目用过的键里挑，请求头还能填 `Bearer ` 前缀，值在下方「引用的凭据」里填——不需要知道（也不会看到）底层的占位符写法。
- profile 的 `cordis.patch.yml` 里已有的 MCP 行只读展示（URL 去查询串、stdio 只给命令名与参数个数、env/header 只给键名），并提供「导入为托管条目」。
- 状态页每台服务器只占**一行**（左：启停开关；中：名称 + 工具命名空间 + 状态标签；右：编辑、删除），把鼠标停在这枚「已连接 · N 个工具」标签上会弹出**完整工具清单**——用 DSH 自带的 Tooltip，浮层宽高不超出设置面板，长清单可在标签上滚动滚轮翻看；mcp-client 最近的重连/错误日志收在编辑弹窗里。
- 凭据写入后自动重新对账（填完 token 不必再点一次「重新对账」）。
- 导航分区图标用可逆 DOM 补丁换成连接图标（壳层只给 4 个官方分区配图标）。
- 适配 DSH 0.1.7 的设置模型：清单改为本插件在 profile 里的**条目配置**（字段声明 `volatile()`，宿主在「只有它变化」时就地更新引用并触发对账），客户端读写走官方 `configForms`；0.1.6 的 `settings.register('mcp-console')` 独立命名空间已随 DSH 移除，`~/.dsh/settings.yaml` 里不再有本插件的数据（值现在落在该 profile 的 `cordis.patch.yml` 里 `dsh-mcp-console` 那一条的 `config`）。
- 版本线推进到 DSH `>=0.1.7-alpha.1 <0.1.8`（逐版本验证 `0.1.7-alpha.2`；上一线的用户留在上一线的插件版本）。

# dsh-mcp-manager

在 DSH 设置页里管理 MCP（Model Context Protocol）服务器：**增删改、启停、连接与工具状态、凭据**，不用手写 profile 配置、不用重启 `dsh web`。

## 要求

- DSH `>=0.1.7-alpha.1 <0.1.8`（逐版本验证过 `0.1.7-alpha.2`；同线其它版本会带警告运行）。
- `web` profile（设置页插件）。
- 宿主需要有官方的设置通道（0.1.7 起是 profile 条目配置，web profile 自带）才能持久化服务器清单。

## 安装与卸载

```bash
dsh plugin --profile web add dsh-mcp-manager        # 安装 / 升到 caret 范围内的最新版
dsh plugin --profile web add dsh-mcp-manager@0.1.0  # 指定版本（升级必须显式写版本号）
dsh plugin --profile web remove dsh-mcp-manager     # 卸载
```

安装或卸载会改变 profile 的 bundle 列表，**需要重启 `dsh web` 并刷新页面**才生效。源码开发路线用本目录的 `./install.sh` / `./uninstall.sh`。

## 使用方法

打开 **设置 → MCP 服务器**：

- **新增**：右上角 `+` 打开表单弹窗——**不会**先落一条空条目。选 `stdio`（本地进程：命令、参数每行一个、工作目录、环境变量）或 `streamable-http`（URL、请求头）。
- **保存即验证**：点「保存」时宿主会先用临时实例连一次——**连得上才写入**；连不上就把原因显示在弹窗里（不落盘），改完再点保存即可。保存时会显示工具清单，方便确认连对了服务器。
  升级插件后若弹窗提示"宿主进程还是旧版本"并禁用保存，说明宿主进程还在跑旧代码——在终端里 `Ctrl+C` 后重新执行 `dsh web --no-open` 即可（浏览器侧刷新就够，宿主侧必须重启）。
- **编辑**用每行右侧的铅笔图标，同一个弹窗、同样的规则（每次保存都重新验证）。
- **保存即生效**：清单就是本插件在 profile 里的**条目配置**（DSH 0.1.7 的设置模型），写入经官方设置通道落到该 profile 的 `cordis.patch.yml` 里 `dsh-mcp-manager` 那一条的 `config`；保存后宿主立刻对账——新增/改动会挂载，停用/删除会卸载。**不需要重启**。
- **启停**：每行左侧开关。总开关在标题下方，关掉会逐一卸载全部托管服务器。
- **状态**：每行只有一行——左边是启停开关，中间是名字 + 工具命名空间 + 状态高亮标签（已连接 N 个工具 / 配置不完整 / 挂载失败 / 已停用），右边是编辑与删除。鼠标移到「已连接 · N 个工具」这个标签上会弹出**完整工具清单**（浮层不超出设置面板，列表长了可以在标签上滚动滚轮翻看）；其它状态把鼠标停在标签上能看到完整原因。保存后会等宿主完成这一轮对账再显示结果，所以看到的就是实际生效的状态。
- **工具名**：与手写组合行完全一致，形如 `mcp__<服务器名>__<工具名>`。所有会话与子代理都能用；改动对**进行中的对话**在下一步请求生效。
- **删除**：行尾垃圾桶，确认后从清单移除并卸载；**不会**删除已写入的凭据。

### 凭据

密钥不用直接写在环境变量、请求头或地址里——那些值会明文存进这个 profile 的配置里（设置页本来就要读它）。改用「引用凭据」：

1. 在**环境变量** / **请求头**里点一行右侧的 **「凭据」** 开关（地址栏旁边的「凭据」开关则用于「整条地址进凭据库」）；
2. 会多出**键名**字段：**键名自己取**（如 `JIRA_MCP_TOKEN`，合法形式是 `[A-Za-z_][A-Za-z0-9_]*`），也可以点下方「用过的键」里的候选直接选用（只列**别的条目用过、这一条还没用**的键）；请求头多一个**前缀**档位（`不加前缀` / `Bearer` / `Basic` / `其它…`，选「其它」可自己输入任意前缀），`Authorization: Bearer <token>` 这种直接选 `Bearer` 即可；每个字段各占一行，长键名不会看不全；
3. 表单下方随即出现**「引用的凭据」**区：在那里填值并点「保存」——值直接写进 DSH 的凭据库（`~/.dsh/.credentials.yaml`），**界面永不回显**，同一个键能被多条服务器复用、也能复用已有的环境变量；
4. 凭据还没配置时该服务器**不会被挂载**，行上会说明缺哪个键。

底层存进配置的仍是 `credential:键名` 这种占位符（那里只能放字符串），挂载时才由宿主替换成明文——这层细节不用你操心，编辑界面里不会出现它。

### 与 profile 配置文件的关系

MCP 服务器目前也能手写在 profile 的 `cordis.patch.yml` 里（你们机器上的 Figma / Jira 就是这么写的）。本插件：

- 在页面下方以「配置文件中的服务器」只读卡片列出它们：服务器名、传输方式、地址，以及有哪些请求头/环境变量字段——**不显示字段的值**。改它们请直接编辑该文件。
- 每条都能「导入」：把这一条的**完整配置**（地址或命令、参数、工作目录、普通环境变量与请求头、超时）抄成一条可在这里编辑的托管条目，导入后默认**停用**（避免与配置文件里那条同名冲突），改完名字再验证保存即可接管。
- 导入时**敏感字段不会进清单**：请求头/环境变量里名字或值像凭证的（`Authorization`、`*_TOKEN`、`Bearer xxx`…），以及 URL 里带 token 的整条地址，都会被搬进 DSH 的凭据库；弹窗里这些字段直接就是「凭据」形态（名字 + 键名 + 前缀），会说明搬了哪几个键，界面上不回显值。
- 同一个服务器名在整个 host 作用域内只能存在一个实例：托管条目与配置文件条目重名时，托管那条会被拦下并说明原因。

两者最终在同一个文件里：托管清单是 `dsh-mcp-manager` 那一条的 `config`，你手写的 MCP 行是各自的条目。**插件只写自己那一条**，你手写的内容（含注释与 `!!js` 表达式）不会被改写。

## 注意事项与已知边界

- **凭据值必须能被解析**：`credential:KEY` 的明文来自进程环境 / `~/.dsh/.credentials.yaml` / `~/.dsh/.env`（只读兜底）。环境变量来源的值在本插件里是**只读**的。
- **手写在 `cordis.patch.yml` 里的 `!!js process.env.X` 仍需要重启**：`.env` 是进程启动时的快照，与本插件无关；要免重启请改成托管条目 + `credential:KEY`。
- **改配置走「先卸后挂」**：改动会重连该服务器，而不是原地重启连接；期间的进行中调用会失败。
- **`failOnStartupError` 默认关闭**：连不上时照样挂载并自动重连（退避 500ms 起、上限 30s），状态行会显示最近的重连日志；勾上它则启动失败直接记为「挂载失败」。
- **改动不会追溯历史**：已经发生的工具调用记录不变，新设置只影响之后的请求。
- **删除条目只影响托管清单**：profile 配置里其它条目的数据与 `.credentials.yaml` 都不会被动。
- 本插件不改写你手写的配置行，也不修改 DSH 安装内的任何文件；托管清单的持久化由 DSH 官方设置通道负责，写进的是本插件自己那一条的 `config`。

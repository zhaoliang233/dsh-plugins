# 变更记录

## [0.3.1] - 2026-10-19

### 修复

- **修正设置分区 order 并列**：`SECTION_ORDER` 由 `110` 调到 `120`。此前本包与 `dsh-mcp-console` 都用 `110`，构成同一 slot 内的并列——壳层是 `sort((a, b) => a.order - b.order)` 的稳定排序，并列时只能靠注册顺序决胜，属于「同一个 slot 里多个插件不要复用同一档 order」的违反。现在五个插件的分区是 100/110/120/130/140 连续分配（`extra-context` 100 / `local-plugin-manager` 110 / 本包 120 / `mcp-console` 130 / `chat-archive-manager` 140），权威表在根 `AGENTS.md`。**业务代码与全部契约行为未变。**

## [0.3.0] - 2026-10-12

### 修复与新增

- **官方条目被别的 bundle 禁用后，模块不再永久变成「暂时不可写」**：用户开启 `@deepseek-ai/dsh-experimental-session-titles-bundle` 后，它的补丁会把 `session-title-llm` 设成 `disabled: true`、改用 `optional-session-title-all-prompts`（`@deepseek-ai/dsh-session-title-all-prompts-llm`）。此前本插件的白名单按条目标题写死，首选条目失去 fiber 后「会话标题命名模型」模块整块不可写（标签「暂时不可写」、输入框全禁用），而实际生效的 provider 已经换成替代条目。
- 现在白名单条目可以声明**替代条目**（`fallbacks`），宿主按候选优先级挑当前**可写**的那一个：首选可写就用首选，首选被禁用/消失则自动跟随替代条目——读写（含「恢复默认」、标题重算里的抬上限）都落到替代条目上，页面标出「**跟随 `<条目 id>`**」并说明原因。候选全都不可写时仍按原样降级，并给出可诊断的原因。
- 顺手修掉两处会误导的细节：模块标题不再写死条目 id（显示「会话标题命名模型」，实际条目由「跟随 …」标签给出）；字段提示不再硬编码「默认 4096」这类数值（实验条目与官方条目的默认值并不相同，实际默认值以输入框占位符为准）。
- 高级模式把替代条目标为「可在上方调整」（此前它会显示成「只能整块清除」）。
- **关掉实验性插件之后不再"静默丢设置"**：跟随期间覆盖写在替代条目上，一旦提供该条目的实验性插件被关闭，这个条目就从组合里消失——dsh 会忽略这条覆盖（只在启动日志打一条 `patch: entry "X" not found`，界面完全无感），而 `configEditor` 只认组合里的条目，设置页既看不到也清不掉（此前会一直卡在补丁文件里）。现在宿主只读补丁文件、把"补丁顶层有、当前组合里没有"的条目列为**失效覆盖**（新增回执字段 `staleOverrides`），高级模式用「N 条失效覆盖」标签与一段说明提示用户手动清理；跟随状态的模块说明里也补了"关闭前先点「恢复默认」"的前置提醒。插件**不替用户删**这些条目（写入仍然只走官方 `configEditor.edit()`，不绕开事务与文件锁）。
- 模块本身在这条路径上是好的（关掉实验插件后会回落到官方条目并保持可写），这一点同时补了写入与浏览器两端的实测。

## [0.2.0] - 2026-10-10

### 变更

- **首次发布**。此前 0.1.0 一直处于未发布状态；包名 `dsh-default-tuner` 是 2026-10-08 从 `dsh-default-overrides` 改来的（旧名在 npm 上被第三方占用、发不了版；新名同日实测未被占用），改名同步了 profile 条目 id 与模块名（`cordis.patch.yml`）、浏览器 bundle 注册名（`client.js`）、`lib/overrides.js` 的 `PLUGIN_NAME` / `SECTION_ID` / 两条 HTTP 路由 / 两个固定头名，以及内部短前缀（CSS 类名 `ddo-*` → `ddt-*`）。
- **兼容发布线从 `>=0.2.0-rc.2 <0.2.1` 跨到 `>=0.2.1-alpha.2 <0.2.2`**：逐包 diff（28 个契约包 × 2 版、逐文件 sha256，new 侧与运行安装全树逐字一致）后，契约面逐条在 `0.2.1-alpha.2` 的实际安装包里重读——`configEditor.edit()`/`configuration()` **整个文件逐字相同**（"先校验后落盘、`fiber.state !== 2` 拒绝、`!!js` 重建、reconcile 失败回写原文"这条链一行未动）、`dsh-app-boot` 的 `composeEntries`/`readProfilePatches`/`reconcileProfilePatches`/`readProfileManifest` 函数体逐字相同、目标条目 8 个字段仍全是 required 顶层字段、超限文案与 `titleInput` 投影逐字相同、`sessionTitle.get/refresh` 与 `sessions.get/list` 未变、`register()` 与 `requestRejection()` 未变。**业务逻辑一字未改**。
- **默认值跟进官方调整**：DSH 0.2.1 把 `session-title-llm.maxOutputTokens` 的官方默认从 `64` 改成 `4096`，字段提示与 README 的默认值表格同步更新。顺带订正一条官方 `configEditor` 的既有边界：被覆盖条目是补丁里唯一内容时，「恢复默认」会连同块外的注释一起删除。
- 版本门四个常量整体换线，13 档版本矩阵按新下界重设（新增「同线的 `beta`/`rc` 必须放行、`alpha.1` 必须挡住」两条判据）。

## 0.1.0

- 首个版本：新增设置分区「默认设置覆盖」。
- 首批可覆盖项：`session-title-llm`（输入上限、输出上限、生成超时、目标词数、目标字数）与 `session-title`（标题最大字节、兜底词数、兜底字节）。
- 写入走官方 `ctx.configEditor.edit()`：整块写进当前 profile 的补丁文件，保留注释与 `!!js`，失败回滚；「恢复默认」把单项退回继承层默认值，整块相等时自动删除覆盖。
- 高级模式：列出当前 profile 全部带配置覆盖的条目，支持清除某个条目的整块覆盖。
- 会话标题重算：可对单条活跃会话重新生成标题（官方没有这个入口）。**列表只收标题仍是兜底截断的会话**——模型成功命名、手动命名、以及还没生成标题的都不进列表；重算成功后自动从列表消失，之后也不再出现；卡片同时显示「活跃会话总数 / 需要重算数」，说明过滤口径。
- 冻结可见：补丁整块替换会顺带写入同值字段，页面把「我改过的」标为「已覆盖」、把「一起写进去的」标为「随整块写入」，并给出解除方式。
- 列表口径在宿主与页面各筛一遍：宿主过滤减少响应体，页面兜底过滤 + 统计回退，避免宿主尚未重载时（刷新拿到新页面、进程还是旧代码）把全部会话列出来。
- 设置页改为模块化：补上面板标题，去掉「会话标题」分组层，每个模块可折叠且**默认收起**；
  状态文案统一用标签呈现（模块级 / 字段级 / 会话行 / 高级模式行），并修掉窄宽度下按钮被压成两行的问题。
- 四个模块的折叠形态统一成原生 `<details>`：箭头由浏览器绘制（不再自绘三角），hover 反馈一致。
- 高级模式每行补齐可编辑性标签（`可在上方调整` / `只能整块清除`），并在列表上方给出一句说明。
- 界面控件改为复用官方 `dsh-client-ui-primitives`：折叠箭头用官方图标（不再自绘或依赖浏览器 marker），状态标签用官方 `Tag`，按钮与输入框用官方 `Button`/`Input`。
- 修掉高级模式丢掉折叠箭头的问题：折叠结构收敛到唯一出口，高级模式改走同一组件。
- 标题重算前置预检：按官方口径算出首条消息的输入字节数，首条消息超过「输入上限」的会话单独列为「输入超限」并标出字节数，按钮改为「调大上限并重算」（先抬上限再重算）；provider 的超限报错也翻译成中文并附一键修复。
- 守卫：同源 + 客户端标记头 + CSRF 令牌（令牌由 status 下发，action 才比对）。
